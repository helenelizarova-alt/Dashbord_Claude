# Дашборд аналитики WB + Ozon

Каркас: Node.js-сервер без фреймворков + одностраничный фронт. Без ключей работает на демо-данных.

## Запуск

```bash
npm install
cp .env.example .env
npm start
```

Откройте http://localhost:3000. Сервер слушает только `127.0.0.1`. Для доступа извне ставьте его за прокси с авторизацией (nginx + basic auth).

## Ключи API: файл .env

Все ключи лежат в `.env` в корне проекта (образец: `.env.example`). В базу `data/db.json` и во фронт они не попадают: вкладка «Интеграции» показывает только, задан ключ или нет. После правки `.env` перезапустите сервер.

| Переменная | Для чего |
|---|---|
| `WB_TOKEN` | WB: статистика, цены, календарь акций |
| `WB_ADV_TOKEN` | WB Продвижение, если токен отдельный (иначе берётся `WB_TOKEN`) |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | Ozon Seller API |
| `OZON_PERF_CLIENT_ID`, `OZON_PERF_SECRET` | Ozon Performance (реклама) |
| `ANTHROPIC_API_KEY` | ИИ-ассистент (модель `claude-opus-5-5`, `lib/ai.js`) |
| `PORT`, `HOST` | Адрес сервера |

`.env` и `data/` внесены в `.gitignore`, в репозиторий они не попадут.

## Структура

| Файл | Что делает |
|---|---|
| `server.js` | HTTP-сервер, JSON API, фоновая синхронизация (раз в 3 часа и по кнопке «Обновить») |
| `lib/wb.js` | WB: заказы, остатки, отчёт о реализации, цены, реклама (Продвижение), календарь акций |
| `lib/ozon.js` | Ozon Seller: цены, остатки, аналитика заказов, финансовые транзакции, акции; Ozon Performance: реклама |
| `lib/manual.js` | Разбор Excel: реализация WB, цены WB, начисления Ozon, себестоимость, КИЗ |
| `lib/calc.js` | Все расчёты: P&L, KPI, юнит-экономика, реклама, склад, акции, Честный знак, решения, инсайты |
| `lib/demo.js` | Демо-данные (включаются для канала без ключей и без загруженных отчётов) |
| `lib/ai.js` | ИИ-ассистент на Claude API |
| `lib/store.js` | Хранилище `data/db.json` и настройки по умолчанию |
| `lib/env.js` | Чтение ключей из `.env` |
| `public/` | Фронт: `index.html`, `style.css`, `app.js` |

## Как считается

* **Финансы** берутся из отчёта о реализации WB и транзакций Ozon (API или Excel). Ручной отчёт заменяет данные API за свой период.
* **Дни без финотчёта** (у WB это последняя неделя) считаются по заказам: процент выкупа, комиссия и логистика берутся из настроек. Такие строки помечены `*`, а в «Центре решений» есть напоминание.
* **Реклама:** WB берётся из Продвижения. Ozon берётся из Performance API, а без него из рекламных услуг в финансах. Расход без привязки к артикулу делится по доле выручки.
* **Постоянные расходы** делятся между каналами по доле чистой выручки.
* **Цена безубытка** = (себестоимость + логистика/ед + реклама/ед) / (1 − комиссия − налог). Цена для целевой маржи считается так же, но ещё минус целевая маржа.

## Что проверить перед боевым запуском

1. Эндпоинты WB и Ozon (WB часто меняет версии). Особенно `adv/v3/fullstats`, `calendar/promotions`, `v5/product/info/prices`, `statistics/daily/json`.
2. Разнесение услуг Ozon по статьям (`ozKind` в `lib/ozon.js`) на реальном отчёте.
3. Названия колонок в ваших Excel-файлах (`aliases` в `lib/manual.js`).
4. Срок вывода КИЗ из оборота (настройка «Срок вывода КИЗ») по актуальным правилам ГИС МТ.

## Чего нет в каркасе (этап 2)

* Автоматическая выгрузка КИЗ по FBS-заказам из API (сейчас загрузка файлом) и автовывод в ГИС МТ (нужна электронная подпись).
* Поставки из API WB/Ozon (сейчас ведутся вручную).
* Авторизация пользователей и несколько кабинетов.
